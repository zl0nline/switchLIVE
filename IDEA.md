# switchLIVE — стенд для тестирования коммутаторов

## Суть

Утилита для быстрого тестирования коммутаторов, возвращаемых из сети.
Коммутаторы разных производителей: Cisco, D-Link, Eltex, Huawei, Edge-Core.
Обычно 10–48 портов, медь / SFP / SFP+ / PoE.

MVP делаем на Python 3 с минимальным набором зависимостей. Детали стека описаны в [TECH_STACK.md](TECH_STACK.md).

## Режим работы — walk-test

Все порты сразу не подключаем. Оператор переставляет один тестовый кабель/устройство по портам, а Linux-ноутбук или мини-ПК через отдельный консольный кабель управляет коммутатором.

Сценарий:
1. Оператор вставляет тестовый кабель в порт.
2. Утилита видит `link up`.
3. Определяет порт на коммутаторе (MAC table, SNMP counters, ifOperStatus, LLDP/CDP).
4. Тестирует порт.
5. Делает `shutdown` порта — сигнал оператору: можно переставлять кабель.

## Стартовое меню

При запуске утилита показывает меню с кнопкой **«Определение коммутатора»**:
- автопоиск по всем доступным COM-портам;
- автоопределение модели и прошивки;
- попытка авторизации через стандартные данные из файла `standart_login.txt`;
- если стандартные данные не подошли — поле для ручного ввода логина/пароля оператором.

## Консольный интерфейс

С утилитой должно быть приятно работать даже в консоли:
- аккуратные меню и понятные шаги мастера;
- красивые статусы с иконками;
- прогресс-бары для теста порта, iperf-прогона, PoE-ожидания и полного обхода коммутатора;
- спиннеры/анимации для ожидания COM-порта, ответа коммутатора и загрузки PoE-камеры;
- цветовая индикация OK / WARN / FAIL;
- понятные сообщения на русском языке без лишнего технического шума;
- по возможности не тянуть тяжелые UI-зависимости ради красоты.

## Железо стенда

- Linux-ноутбук или мини-ПК
- USB-UART / RJ45-serial консольный кабель → в коммутатор
- Ethernet-кабель из тестового хоста → переставляется по портам
- PoE IP-камера — отдельный тестовый зонд для PoE-портов
- Для SFP/SFP+: отдельный SFP-интерфейс, DAC/оптика/модуль, желательно DOM

## Тесты

### Ethernet-порты
- link up/down
- speed / duplex
- флапы, стабильность линка
- CRC / drops / counters
- прохождение трафика
- обучение MAC

### Тестирование трафиком (iperf)

Отдельный ноутбук/ПК с запущенным `iperf` в режиме сервера подключается Ethernet-кабелем в тестируемый порт.
Хост с консолью запускает `iperf`-клиент и прогоняет тест трафика.

Логика:
1. IP хоста с iperf-сервером берётся из конфига.
2. Если в конфиге IP нет — оператор вводит вручную.
3. Утилита проверяет доступность iperf-сервера: «хост обнаружен».
4. Приступаем к тестированию портов.

### PoE
- питание: выдаётся или нет
- мощность / class / status / fault
- загрузка PoE-камеры и её видимость по сети

### SFP / SFP+
- линк / скорость
- DOM: RX/TX power, температура
- vendor / serial модуля

## Управление коммутатором

Базово — через консоль (USB-UART), потому что после сброса IP/пароли/SNMP могут быть неизвестны.

Нужны CLI-адаптеры под:
- Cisco IOS
- Huawei VRP
- Eltex
- D-Link
- Edge-Core

Первый этап поддержки начинается с D-Link. Список стартовых моделей лежит в [SUPPORTED.md](SUPPORTED.md).

## Таймауты

Динамический режим:
- обычный порт: ~10–30 сек;
- PoE-камера: 60–180 сек (камера может долго грузиться);
- если коммутатор медленный после CLI-команды — таймаут расширяется;
- если виден прогресс (MAC появился, IP ещё нет) — не рубить, а продлить ожидание.

## Отчёт

Содержимое:
- модель, серийник, прошивка
- дата, оператор
- результат каждого порта (Ethernet отдельно, PoE отдельно)
- итог: **PASS / PASS WITH WARNINGS / FAIL / UNMANAGED**

Формат: открытый вопрос (HTML / PDF / CSV).

## История тестов

SQLite без сервера:
- серийник, модель, прошивка
- даты тестов
- результаты по портам
- оператор, комментарии

Цель — видеть повторные возвраты и повторяющиеся неисправности.

## Открытые вопросы

- Формат отчёта (HTML / PDF / CSV / всё сразу)
- Нужны ли инвентарные номера
- Профили тестов и выбор режима — вручную или автоопределение
